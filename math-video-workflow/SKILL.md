# Math Video Workflow

把一集手机录制的数学讲解推进到可发布成片。它只管阶段、交接和确认；剪辑、内容审校、Manim 各由专用 skill 完成。

## 何时使用

- 开始、继续或收尾一集 `P1`、`P2` 等分集视频
- 不确定当前做到哪一步或下一步该调用哪个 skill
- 需要在本地处理与 API 判断之间做成本/质量取舍

## 单一状态源

每集目录保存一份 `workflow.yaml`，它是机器可读的唯一状态源；README 只解释内容和链接，不重复阶段状态。首次处理时从 [模板](templates/workflow.yaml) 复制。

视频大文件留在视频工程目录；学习仓库只保存课程映射、学习记录和 Manim 工程。路径全部从 `workflow.yaml` 读取，不从聊天记忆猜测。

## 阶段

按顺序推进，每次只执行一个阶段：

1. **Intake**：确认 episode、源文件、课程、目标画幅和交付物；用 `ffprobe` 记录真实流信息。完成条件：源文件可读，路径和探测结果已写入状态文件。
2. **Transcribe**：调用 `video-smart-cut` 生成原片轴转写。完成条件：转写 JSON、SRT、TXT 均存在，且来源指纹与本次源文件一致。
3. **Light review**：调用 `math-video-review` 检查核心术语、公式候选和疑似口误。完成条件：问题清单有时间戳与证据；未确认项保持“疑问”，不自动改正。
4. **Cut**：用户确认粗剪策略后调用 `video-smart-cut`。完成条件：剪辑决策、字幕映射和预览成片通过结构校验与抽查。
5. **Final review**：对剪后字幕、画面方向、数学表达和音频做终审。完成条件：所有阻断项已解决或由用户明确接受。
6. **Deliver**：输出无特效、无 BGM 的最终横版成片和外挂字幕；是否烧录字幕由状态文件指定。完成条件：完整解码、时长、流规格、首中尾抽查均通过。
7. **Animation candidates**：调用 `math-video-review` 只生成 Manim 候选清单。完成条件：每个候选写明教学目的、所需证据和预计场景；默认停在这里。
8. **Manim 插入段（可选）**：仅在用户批准场景后走插入路径——先 `math-manim-insertion` 写场景并出低清预览，预览获批后正式渲染，再由 `manim-video-insertion` 按字幕语义建立插入时间表并装配。完成条件：时间表记录 `scene/start/end/duration/reason/source_srt_entries`，低清预览获批，装配后总时长与源音频一致且每个插入点抽帧通过。
9. **Manim 片尾重温段（可选，独立于第 8 步）**：仅当用户明确要求片尾独立重温段时调用 `manim-recap-video`。完成条件：低清预览获批后才正式渲染并拼接。

## 人工门

以下判断必须暂停并展示证据：

- 删除可能承载思考节奏或句意的片段
- 把 ASR 文本判为口误，或把字幕改成与实际发音不同的数学表述
- 选择画面旋转、裁剪与分段边界
- 确认 Manim 候选、脚本与预览
- 确认插入时间表（替换区间边界）
- 删除、覆盖、移动原片或最终产物

## Local-first 决策

先用本地确定性工具：`ffprobe`、`ffmpeg`、本地 ASR、规则校验和已有脚本。仅当任务需要语义判断且本地方案不能可靠完成时，才把最小必要的文字片段交给厂商 API；视频、音频和完整转写默认不上传。选择标准是端到端效率与正确性，不为“全本地”牺牲可验证结果。

## 恢复与交接

继续任务时先读 `workflow.yaml`，再验证其中记录的产物，不以文件大小、修改时间或旧聊天结论代替验证。每个长任务记录命令、PID/任务句柄、日志、退出码和输出路径；中间分片只有在最终产物完整解码通过后才可申请清理。

## 完成报告

只报告：产物路径、已通过的检查、用户接受的例外、尚未完成的阶段。完成所有指定交付物才把 episode 标为 `done`。
