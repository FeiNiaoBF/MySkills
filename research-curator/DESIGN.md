# Contract v1
Module: `researchcurator`. Public model package: `researchcurator/curator`. The renderer must expose `visualizer.Render(runJSON []byte) ([]byte, error)`; CLI imports it, never the reverse. Renderer consumes JSON; use DOM textContent or escaped templates, escape script-embedded JSON including `</script`, and allow only HTTP(S) links. No CDN or network dependencies.

Run JSON keys (all required): `version` ("1.0"), `id`, `metadata`, `rejected_sources`, `contract`, `sources`, `claims`, `conclusions`, `graph`, `queries`, `events`, `decisions`, `stages`, `coverage`. Arrays are non-null; objects are required. Contract: `question`, `types`, `excludes`, `freshness` (string, human criterion), `preferences`, `quantity` (positive integer), `depth` (string), `questions` [{id,text}]. Sources: id,url,title,type,original (bool),published_at (optional RFC3339),retrieved_at (RFC3339),content (exact retained extract),content_hash (optional computed SHA256),upstream_ids ([]source IDs),freshness (string),fit/evidence/utility (0..1),fit_reason/evidence_reason/utility_reason (nonempty separate reviewer explanations),status (selected/rejected/duplicate/superseded),reason,duplicate_of (optional source ID),verification (verified/unverified/failed). Source verification means human-recorded retrieval verification, not automated truth checking. `fit` measures match to the contract, `evidence` measures quoted primary support, and `utility` measures usefulness for the requested output; these are supplied assessments, not inferred scores. Types, exclusions and freshness criteria are adjudicated by the researcher and explained in source reasons; the engine cannot verify their semantics.

Claims: id,text,question_ids,evidence [{source_id,quote,locator,relation,verification}]. `relation` is supports or contradicts. Quotes must occur exactly in retained source content and locator must be nonempty. Conclusions: id,text,claim_ids,status (verified/unverified/failed); verified requires verified quoted evidence. Graph: nodes [{id,type,label}], edges [{from,to,type}]. Node types Goal/Question/Claim/Source/Conclusion. Node IDs match entity IDs; exactly one Goal uses run.id. Edge directions: contains Goal→Question; addresses Question→Claim; supports and contradicts Source→Claim or Claim→Conclusion; duplicates Source→Source; derives_from Source→Source (downstream→upstream), Claim→Claim, Conclusion→Claim; replaces Source→Source (new→old). Cycles in provenance are flagged and invalidate independent evidence, not silently erased.

Queries: {id,question_id,text,at}. Events: {id,at,stage,action,detail}, optionally before_count/after_count/count_scope together. Counts are nonnegative integers; scope `candidates` counts all source records regardless status, `selected_sources` counts only status selected, before/after the named action. No counts are inferred from prose or retroactively fabricated. Decisions: {id,at,source_id,action,reason}. Stages: {name,status,evidence_ids,reason}; status verified/unverified/failed. Verified stage needs recorded event/query/decision/entity IDs, but this records an assertion, not semantic proof. Names: Requirement First, Discovery, Normalize, Deduplicate, Qualify, Verify, Claim Extraction, Evidence Graph, Coverage Check, Rank, Synthesis. Coverage: {status,questions:[{question_id,claim_ids,independent_sources,gaps}],warnings:[]}. Verified contradictions from any retained source, including rejected/duplicate/superseded sources, remain unresolved gaps and prohibit verified conclusions. Rejecting a source does not resolve a contradiction; this contract intentionally has no automatic conflict-resolution shortcut. Coverage support is calculated from selected sources with verified, quoted evidence; common upstream roots count once. Status verified means requested evidence/quantity is covered, not that every stage ran or the claims are true.

## Execution metadata and rejection index

`metadata` is required: `{created_at, completed_at, status, tools, search_provenance}`. created_at is RFC3339; completed_at is an empty string until finalization, then RFC3339 not earlier than created_at. status is `in_progress`, `finalized`, or `failed`. `tools` is a non-null array of actual tool names (may be empty when no tools were used); `search_provenance` is nonempty prose describing search providers, receipt locations, scope and limitations, without secrets. Individual queries remain in `queries`. `finalized` means the ledger was sealed, not that coverage, every stage, or every claim is verified. A finalized run may explicitly retain unverified coverage.

`rejected_sources` is a required non-null array of `{id,reason}` indexing every nonselected source: rejected, duplicate and superseded. Full records always remain in `sources`. In-progress indexes may be empty or partial; supplied entries must reference nonselected sources and exactly match their reasons. Finalized indexes must be complete. Finalize generates the index deterministically by ID, computes coverage, sets status and a real completion timestamp; repeated finalization preserves the timestamp.

## Component boundaries

Research Engine (`curator/engine.go`) consumes retrieved and assessed evidence; it does not fetch pages or infer assessments. Graph Model (`curator/model.go`, `curator/validate.go`, schema) specifies entities, relationships and integrity, independently of engine execution. Run Recorder (`curator/recorder.go`) appends validated query/event/decision records and persists JSON, without conducting research. Visualizer (`visualizer/`) consumes serialized JSON only, without invoking engine/recorder. Sharing the curator Go package does not merge these responsibilities. The CLI composes components. `graph.nodes` and `graph.edges` are nested, not top-level; edge endpoints are `from`/`to`. Required `contains` edges connect Goal→Question for every contract question; required `addresses` edges connect Question→Claim for each claim.question_ids membership. Source→Claim evidence edges remain supports/contradicts, so traversal is Goal→Question→Claim←Source. Extra addresses edges not recorded in question_ids fail.

Source→Claim evidence edges and quoted evidence records must match in both directions; unsupported graph-only assertions fail validation. Claim→Conclusion support/derivation must match conclusion.claim_ids. An explicit Claim→Conclusion contradiction is retained for unverified conclusions, adds a coverage warning, and prohibits a verified conclusion; dismissing an opposing claim is not an automatic resolution mechanism. Provenance root resolution is memoized; depth is bounded at 256 and root-analysis operations at 100,000. Exceeding a budget produces an explicit warning and unverified coverage, never a silent claim of complete analysis. Cached root sets are immutable during corroboration-group merging.

Strict schema lives in schema/run.schema.json. Go validates the exact supported schema keywords (type, required, properties, additionalProperties, items, enum, minimum, maximum, minLength, minItems) before decoding and then checks semantic references, quotes, graph and status assertions. Unknown fields and missing objects fail. Dates and URL safety are checked semantically. Rank uses fit 50%, evidence 30%, utility 20%, deterministic ID ties, selected sources only; it cannot decide relevance from source text.
