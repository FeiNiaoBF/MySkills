# Contract v2 (run.json version 2.0)
Module: `researchcurator`. Public model package: `researchcurator/curator`. The renderer must expose `visualizer.Render(runJSON []byte) ([]byte, error)`; CLI imports it, never the reverse. Renderer consumes JSON; use DOM textContent or escaped templates, escape script-embedded JSON including `</script`, and allow only HTTP(S) links. No CDN or network dependencies.

Run JSON keys (all required): `version` ("2.0"), `id`, `metadata`, `rejected_sources`, `contract`, `sources`, `claims`, `conclusions`, `graph`, `queries`, `events`, `decisions`, `adjudications`, `stages`, `coverage`. Arrays are non-null; objects are required. Contract: `question`, `types`, `excludes`, `freshness`, `preferences`, `output:{target_sources}` (positive integer), `coverage:{min_independent_origins}` (positive integer), `depth`, `questions` [{id,text}]. The fields have separate meanings: desired selected output count versus minimum independent original-evidence groups. Sources: id,url,title,type,original (bool),published_at (optional RFC3339),retrieved_at (RFC3339),content (exact retained extract),content_hash (optional SHA256),upstream_ids, freshness, fit/evidence/utility (0..1), fit_reason/evidence_reason/utility_reason, status (selected/rejected/duplicate/superseded), reason, duplicate_of, verification. Source verification means human-recorded retrieval verification, not automated truth checking. Assessments are not inferred scores.

Claims: id,text,question_ids,evidence [{source_id,quote,locator,relation,verification}]. Quotes must occur in retained source content and have locators. Conclusions: id,text,claim_ids,status. Graph nodes are Goal/Question/Query/Claim/Source/Conclusion; edges include `searched_by` Question→Query and `candidate` Query→Source, plus the explicit evidence relationships documented below. Every query records `provider`, `tool`, `retrieval_reference`, and `candidate_source_ids`; the candidate list and graph edges must agree in both directions. Candidates remain full Source records with their final selected/rejected/duplicate/superseded state; discovery provenance is not discarded after ranking.

Queries: {id,question_id,text,at,provider,tool,retrieval_reference,candidate_source_ids}. Every query is a typed graph node connected from its Question and to each candidate Source; array and edges must match. Events: {id,at,stage,action,detail}, optionally before_count/after_count/count_scope together. Decisions: {id,at,source_id,action,reason}. Stages: {name,status,evidence_ids,reason}. Coverage summary includes selected_sources, target_sources, target_sources_met, independent_sources, min_independent_origins, questions and warnings. Each question counts selected sources with verified supporting quotations; conflicts block verified claims unless a valid explicit adjudication resolves them. The output target and independent-origin minimum are both required for verified coverage. Common upstream roots count once. Coverage verification records completeness against the contract, not truth or research stage completion.

Conflict adjudications are separate `adjudications` records: {id,target_type,target_id,claim_ids,source_ids,status,rationale,evidence,outcome,final_effect}. Status is resolved/unresolved; every record needs rationale; a resolved record additionally needs an explicit supported/rejected outcome, final effect, and one or more verified, quoted, located evidence dependencies from a selected source. Its claims and sources must match both sides of an actual recorded conflict. A source's rejection/duplicate/superseded status never resolves a conflict. Verified claims remain blocked by any verified contradiction unless the matching claim adjudication is resolved with `supports_claim`; a `rejects_claim` result blocks conclusions relying on that claim. Conclusion conflicts are resolved separately and never inherit claim adjudications. An unresolved conflict continues to block verified coverage/conclusions.

## Execution metadata and rejection index

`metadata` is required: `{created_at, completed_at, status, tools, search_provenance}`. created_at is RFC3339; completed_at is an empty string until finalization, then RFC3339 not earlier than created_at. status is `in_progress`, `finalized`, or `failed`. `tools` is a non-null array of actual tool names (may be empty when no tools were used); `search_provenance` is nonempty prose describing search providers, receipt locations, scope and limitations, without secrets. Individual queries remain in `queries`. `finalized` means the ledger was sealed, not that coverage, every stage, or every claim is verified. A finalized run may explicitly retain unverified coverage.

`rejected_sources` is a required non-null array of `{id,reason}` indexing every nonselected source: rejected, duplicate and superseded. Full records always remain in `sources`. In-progress indexes may be empty or partial; supplied entries must reference nonselected sources and exactly match their reasons. Finalized indexes must be complete. Finalize generates the index deterministically by ID, computes coverage, sets status and a real completion timestamp; repeated finalization preserves the timestamp.

## Component boundaries

Research Engine (`curator/engine.go`) consumes retrieved and assessed evidence; it does not fetch pages or infer assessments. Graph Model (`curator/model.go`, `curator/validate.go`, schema) specifies entities, relationships and integrity independently of engine execution. Run Recorder (`curator/recorder.go`) appends validated query/event/decision/adjudication records and persists JSON. Visualizer (`visualizer/`) consumes serialized JSON only. `graph.nodes` and `graph.edges` are nested; edges use `from`/`to`. Required paths include Goal→Question (`contains`), Question→Query (`searched_by`), Query→Candidate Source (`candidate`), and Question→Claim (`addresses`); source evidence edges match recorded quotations. The selected/rejected/duplicate/superseded Source stays linked to its discovering query. The CLI composes modules; no retrieval logic is in the UI.

Source→Claim evidence edges and quoted evidence records match both ways; Claim→Conclusion support/derivation matches conclusion.claim_ids. Verified contradictions in any retained source, rejected or otherwise, are not suppressed by changing candidate status. Only an explicit matching resolved adjudication with verified supporting dependencies may permit the corresponding supported claim/conclusion; an adverse or unresolved adjudication blocks verified status. Provenance traversal remains memoized and bounded (depth 256, 100,000 operations); exhaustion is visible and leaves coverage unverified.

Strict schema lives in schema/run.schema.json. Go validates the exact supported schema keywords (type, required, properties, additionalProperties, items, enum, minimum, maximum, minLength, minItems) before decoding and then checks semantic references, quotes, graph and status assertions. Unknown fields and missing objects fail. Dates and URL safety are checked semantically. Rank uses fit 50%, evidence 30%, utility 20%, deterministic ID ties, selected sources only; it cannot decide relevance from source text.
