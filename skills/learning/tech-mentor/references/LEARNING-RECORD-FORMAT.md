# Learning Record Format

Learning records live in `./learning-records/` and use sequential names such as `0001-render-loop.md`. They capture non-obvious, evidence-backed changes in what the learner can do or explain; they are not session diaries.

## Template

```md
# {Short title of the capability or insight}

{1–3 sentences describing what changed and why it matters for the next project.}

## Evidence
{The project, test, output, explanation, or prior experience that supports the claim.}

## Implications
- {What this unlocks}
- {What should no longer be re-taught}

## Transfer check
{A short changed requirement, repair, or rebuild that would verify this capability later.}
```

## Optional status

Add `Status: superseded by LR-NNNN` when a later record corrects or deepens the earlier understanding. Preserve the earlier record so the path of the misconception remains useful.

## When to write one

Write a record when the learner demonstrates a non-trivial capability, discloses meaningful prior knowledge, corrects a misconception, or changes the mission in response to evidence. Coverage alone is not evidence of learning.

Do not duplicate a concise term definition already in `GLOSSARY.md`, and do not turn records into activity logs.
