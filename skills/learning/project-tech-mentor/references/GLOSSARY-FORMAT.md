# GLOSSARY.md Format

`GLOSSARY.md` is the canonical language for one technology workspace. It reduces overloaded terms and keeps project briefs, explanations, and learning records consistent.

## Template

```md
# {Technology} Glossary

{One or two sentences describing the vocabulary boundary of this workspace.}

## Terms

**{Term}**:
{A tight definition of what the term is, in one or two sentences.}
_Avoid_: {A misleading synonym or ambiguous phrase}
```

## Rules

- Add a term after the learner can use it correctly; this is a record of compressed understanding, not a dictionary to read first.
- Pick one preferred term when aliases compete, and list the aliases to avoid.
- Use the glossary's established terms inside later definitions and project briefs.
- Group terms under domain clusters when that makes the map easier to navigate.
- State local resolutions for ambiguous terms, such as what “latency” means in this workspace.
- Revise a definition when the learner's understanding becomes more precise; do not leave stale wording beside the new one.
