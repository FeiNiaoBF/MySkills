# Method map

On-demand detail for Step 4 of `SKILL.md`. This is a defeasible heuristic, not a fixed menu: problem structure constrains the kind of answer and evidence, but it does not select a unique method. Several methods can answer the same question, and mixed methods are often appropriate.

## Selection rules

1. **Name the answer type.** Description, explanation, prediction, evaluation, decision, design, interpretation, or negotiation.
2. **Name the discriminating observation.** What would you see if one live possibility were true and another false?
3. **Check feasibility.** Do you have access, time, ethical clearance, and authority to run the method? A method you cannot run cannot change the recommendation.
4. **Match rigor to reversibility.** Use the cheapest method that can discriminate; reserve expensive or irreversible methods for decisions where being wrong is costly.
5. **Allow "no theory".** Description, a decision rule, or a direct observation may be enough. Theory is useful when it predicts, explains a mechanism, or exposes an assumption.

## Map

| Problem | Useful modes | Theory's job | Characteristic failure |
|---|---|---|---|
| Causal explanation | comparison, process tracing, natural experiment, statistical control | supply mechanisms, confounders, scope conditions | correlation mistaken for cause; selection; reverse causation |
| Prediction | base rates, reference-class forecasting, scenarios, models | supply causal structure and priors | false precision; regime change; overfitting |
| Interpretation or meaning | interviews, ethnography, document and discourse analysis | supply sensitizing concepts, not the answer | imposing the analyst's frame; treating one voice as the culture |
| Evaluation | criteria from purpose and stakeholders, counterfactual, cost-benefit, distributional analysis | supply criteria and causal mechanisms | hidden norms; measuring what is easy |
| Decision under uncertainty | expected value, minimax, real options, decision matrix | supply priors and structure | false precision; ignoring reversibility |
| Design | constraints, prototypes, trade-off analysis, safe-to-fail experiments | supply patterns and precedents | solutionism; ignoring implementation |
| Value conflict | deliberation, stakeholder analysis, ethical frameworks, negotiation | clarify values and trade-offs, not settle them | technocracy; pretending evidence decides |
| Wicked or unstructured | problem structuring, frame reflection, participatory mapping, scenario planning | supply alternative framings | premature consensus; analysis paralysis |

## Theory selection

Use a theory only when it does real work. Ask:

- What does this theory predict that a rival does not?
- Which assumptions are load-bearing, and are they plausible here?
- What observation would count against it?
- What does it illuminate, and what does it hide?
- If two theories fit the same facts, which makes the more discriminating prediction?

If the theories are empirically equivalent for this decision, say so and choose by decision relevance rather than by disciplinary preference. Do not name a theory as decoration.

## Common combinations

- **Causal + design:** compare cases to find the mechanism, then prototype an intervention that targets it.
- **Interpretation + evaluation:** establish what the problem means to the people affected, then judge options against those meanings and the stated purpose.
- **Prediction + decision:** use scenarios or reference classes, then apply a decision rule that accounts for reversibility and downside.
- **Wicked + participatory:** use frame reflection and stakeholder mapping, then run a bounded safe-to-fail probe with a review trigger.

## Anti-patterns

- Running a method because it is available, familiar, or prestigious.
- Treating a typology label as a finding.
- Using a quantitative method for a value conflict, or a deliberation for a factual question.
- Asking for more data when the decision is about authority or values.
- Forgetting implementation: a method that produces a recommendation no one can execute is incomplete.
