# README 与多语言规则

从 [project-docs](../SKILL.md) 拆出的按需参考；任务涉及 README 入口、结构或多语言版本时读。

- 先确认合适的入口。正式项目缺少项目级入口时通常使用 README；已有有效文档站、模块入口或用户指定范围时，只在导航确实受影响时更新 README。整理上游已确认结论时，可按规划规则选择项目简报，不强制同时创建 README。
- **README 按读者决策路径组织。** 让读者先判断项目用途和适用性，再找到最小可运行用法、安装或设置步骤，以及 API、限制和深入资料入口。具体顺序按项目类型和读者任务调整，不套用固定目录；读者应能在早期确认项目是否适合自己。
- **区分 README 的读者。** README 通常面向评估或使用项目的人。发布流程、CI 维护、内部调试等仅服务维护者的内容，若已有合适的贡献指南或文档位置，应移到那里并从 README 链接；迁移时保留原有有效信息，不因精简而丢失。若 README 的主要读者本来就是维护者，则按其任务组织，不强行拆分。
- 审查或重写 README 时，除通用读者任务检查外，留意开头过早出现内部实现细节、同一事实重复、内容仍以单一集成或工具为中心、详细 API 资料缺少入口，以及过期的相对链接或支持范围。已有的事实核验与链接检查规则仍适用，不重复执行无关的全库盘点。
- 大幅调整 README 结构前，检查相关测试或 CI 是否依赖具体标题、措辞或文件列表；若发现此类约束，优先确认其保护的实际要求，并在必要时调整检查以验证要求而非固定文案，说明理由。无需为普通局部修订例行搜索整个 CI 配置；工作区改动仍按本流程开头的规则保护。
- 维护多语言 README 时，核对各语言版本中的关键事实、限制、操作和链接是否一致，并更新因标题变化而失效的锚点。译文按目标读者的语言习惯组织；不要求章节、表格或标题数量机械相同。
