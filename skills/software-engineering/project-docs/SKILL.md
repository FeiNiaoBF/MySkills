# project-docs

从项目证据出发，让读者能找到、理解并使用信息。以信息充分、职责清楚为约束，减少需要独立维护的文档；不要把文件少等同于文档好。

本文和参考中的“必须”是执行约束；“建议”“默认”可根据项目事实调整并说明理由。

## 执行流程

### 1. 确定范围并读取证据

- 识别用户要的是规划、编写、审查还是维护，以及涉及的项目、功能和版本。沿用已给出的目标，不重复访谈。
- 读取适用的项目约定、文档入口和本次相关材料，再沿信息缺口检查代码入口、接口、配置、测试或需求记录。局部文档修改不启动全仓库重建。
- 先检查工作区改动，保留用户内容。仓库外的 Wiki、需求系统或文档站也可能是权威来源；无法访问时报告缺口，不擅自替代。
- 区分当前实现、已确认需求、已确认决策和未决方案。具体冲突按 [规划规则](references/planning-rules.md) 的“证据与冲突”处理。
- 只有缺失信息会改变文档含义、范围或正确性时才提问；继续处理不受影响的部分。需要探索项目想法时，将具体缺口交给用户或 `grill-me` 等上游工具；不自行扩展成需求访谈。

**完成条件：**知道本轮读者任务、处理范围、主要证据及尚未确认的部分。

### 2. 选择最小充分的文档变更

涉及新文档或结构调整时读取 [Documentation Planning Rules v0.3](references/planning-rules.md)。局部修订只查相关规则。先定位信息的权威维护位置，再决定文件。

对受影响的信息给出紧凑的规划记录：

| 信息 / 读者任务 | 来源与状态 | 权威位置（文件或章节） | 动作与理由 | 验证方式 |
| --- | --- | --- | --- | --- |

仅列本轮涉及的条目；简单修订用一句话代替表格。已有权威信息可以只链接，不要求搬入仓库。规划记录默认放在回复中，不另建规划、盘点或审查报告文件，除非用户或项目流程需要持久保存。

- **仅规划：**交付动作、必要时的目标目录、理由及未决项，到此结束。
- **仅审查：**先报告影响读者的具体问题、位置、证据和最小修复建议；不要直接改写。
- **已授权编写或维护：**按规划执行，不为常规局部修改重复请求批准。涉及外部发布或实质改变需求、决策时，遵循相应授权与评审流程。

**完成条件：**每个新增文件都有读者任务和独立存在的理由；每项信息只有一个权威维护位置。若现有结构已满足任务，可以不改。

### 3. 写作与维护

- 默认先完善正式项目的 README 入口。已有文档站、模块入口或用户指定任务更适合作为起点时，从那里开始。
- 先写读者要知道的结论或要完成的动作。使用一致术语、具体动词和明确条件；一句话尽量表达一个主要意思，不强套英文语法或词数限制。
- 按项目语言写正文，保留代码标识符和准确命令。首次使用必要术语时解释；只有跨文档反复出现且容易混淆的概念才考虑独立术语表。
- 操作说明包含必要前提、步骤、预期结果及适用限制；把条件放在动作之前。对会修改数据或环境的命令说明影响，验证使用隔离样例，遵守任务授权。
- 参考资料优先从已有代码注释、Schema 或 CLI 帮助生成。生成产物修改源头，不另建人工副本；项目专属解释和任务示例仍可人工维护。
- 摘要、示例和引用服务于当前读者；完整契约、需求或参数表只在权威位置维护。读者不应为了理解一句话连续跳转多份文档。
- 图表只用于更清楚地表达关系或比较；架构图不能只列目录名。不给每个文件强套同一套章节、元数据或模板。
- 历史设计保留当时的状态和范围；当前行为放在持续维护的说明中。移动或合并时更新已知引用和导航；公开链接需要重定向或过渡入口时按发布约定处理。
- 示例采用占位符，不写入凭据、用户隐私或机器专属路径。只修改本轮范围内的文档及必要链接，不顺带修复实现。

### 4. 验证与交付

按本轮变更验证，不为文档数量或测试数量扩展工作：

1. **事实：**核对命令、路径、参数、接口、版本和状态。关键结论能追溯到代码位置、适用版本或已确认记录；不会从测试通过推断全部行为正确。
2. **使用：**能安全执行时，在隔离环境验证受影响的快速开始或示例，观察实际结果。无法执行时明确写“仅静态核对”及原因；未验证的步骤不能声称可用。
3. **阅读：**从入口模拟目标读者完成一次任务或查找一条信息，检查必要前提、预期结果和导航是否充分。
4. **结构：**检查重复权威内容、失效入口、相对链接和渲染；运行项目要求的文档检查。没有此类检查时，不为本次写作引入新工具链。
5. **范围：**审阅完整 diff，确认没有改写已确认需求、捏造决定、误删历史或覆盖用户修改。

交付说明包含：改了什么及原因、文档入口、实际完成的检查、未覆盖的行为和待解决冲突。没有问题也不宣称穷尽正确。

**完成条件：**本轮读者任务有充分信息支持，文档可发现，事实状态明确；未验证项和阻塞项可见。未决项只阻塞依赖它的内容。
