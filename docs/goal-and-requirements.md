# MySkills

MySkills 是个人维护、公开可安装的 Agent Skills 创作源，以 MIT 许可发布。每个 Skill 以 `skills/<category>/<name>/SKILL.md` 为入口，为支持 Skills 的 Agent 提供特定任务的工作流程和按需参考。

## 目标

让同一套经过验证的任务指导能在多台机器、多个宿主 Agent 中按名称被发现、安装和更新，而不依赖仓库目录结构或作者本机环境。

## 问题

任务型指导散落在个人笔记和各项目目录里：无法跨机器复用，也难以判断当前生效的是哪一版。把 Skill 集中成一个可安装源解决两件事：

- 按名称路由——安装后按 Skill 名称请求，不依赖分类路径。
- 单点更新——更新一个 Skill 不牵动其他 Skill，规则和通用命令集中维护一处。

## 使用者

- **安装者**：用 Vercel skills CLI 把选定 Skill 安装到项目级或用户级范围，在自己的项目里按名称请求使用。他们只读 `skills/` 与其安装副本。
- **维护者**：在本仓库创作、校验并发布 Skill。仓库由个人维护，外部贡献不是主要来源，贡献路径仍通过 `CONTRIBUTING.md` 公开。

## 能力

- 按类别组织的 Skill 集合，覆盖视频、设计、学习、沟通、问题探索、软件工程、研究、网络安全等任务域；每个 Skill 只归一个类别。
- 每个 Skill 自包含：入口、按需参考、可选宿主界面元数据和素材都在自身目录内。
- 一致的安装与更新路径：按名称列出、安装、更新、移除；更新默认只作用于指定 Skill，扩大范围需显式要求。
- 仓库级机械校验：布局、frontmatter 和本地链接由校验器判定，内容质量由人工复核。
- 维护记录：设计、研究和实施计划留在 `docs/`，不随 Skill 分发。

## 非目标

- 不承载课程工程、媒体、缓存或用户环境配置；这些留在各自项目。
- 不同步用户的安装选择或恢复清单，也不自动 bootstrap 新机器。
- 不为 Skill 提供统一运行时依赖；所需环境以各 Skill 自身说明为准。
- 不把 `docs/` 中的记录当作当前 Skill 行为的依据。

## 原则

- 同一规则只维护一处：安装与更新集中在 `README.md`，格式与验证规则集中在 `CONTRIBUTING.md`，其余文档只引用。
- 先写可执行步骤和完成条件，再提供按分支读取的参考入口；不要求每次通读全部材料。
- Skill 必须能在另一台机器上独立使用：关键步骤、安全边界和验证条件不能依赖聊天记录或作者机器。
- 破坏性或对外动作（网络与设备变更、Push、发布）先做只读诊断，变更前说明影响、备份、回滚与验证方式，并取得授权。
