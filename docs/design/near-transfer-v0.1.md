# 近迁移能力评估 Skill：v0.1 设计规格

状态：设计草案，尚未实现 Skill，也未验证学习效果。

## 1. 目标与成功标准

用户刚学到一个知识点后，在 AI 不提供答案或提示的情况下，能否把它用于一个稍有不同的新情境？

本 Skill 评估这个局部能力，不以解决当前问题、生成笔记或完成课程为目标。一次成功只能报告为：**用户在本次条件下完成了该知识点的一次近迁移**。不能据此宣称长期掌握、远迁移能力或脱离所有工具的独立能力。

能力证据分为三层：

```text
Guided（有帮助完成）→ Independent（无提示完成同类题）→ Near Transfer（无提示完成变式题）
```

这是证据层级，不是每次都必须重新走完的课程。已有可核验的独立作答可以复用；只有“我懂了”或看过答案，不能跳过独立检查。

### 已确认的范围

- 首版只做近迁移：同一核心技能、不引入新核心知识、无 AI 提示。
- 训练题优先来自教材、课程、题库或用户的真实学习任务。
- 近迁移题主要由 AI 生成，依据用户表现调整，但不能改变评估目标。
- AI 自动检查题目约束，合格后直接出题，不要求用户逐题确认。
- 允许表面、结构和简单情境变化；不做跨章节、跨学科、多知识点综合或开放项目。

### 本草案采用的保守默认

以下是实现建议，不是研究证明的最优配置：

- 每次只评估一个目标、展示一道题；优先只改变一个维度。
- 仅在用户明确请求练习或检验迁移能力时启动；普通答疑不自动转成考试。
- 状态默认保留在当前会话，不自动创建学习档案、日历或提醒。
- 延迟复测可推荐，但不是本次近迁移成功的前置条件；未复测时保持能力标为未知。

## 2. 最小运行流程

| 阶段 | 动作 | 完成条件 |
| --- | --- | --- |
| 定义目标 | 从材料和原题提取一个核心技能、已有先备知识、成功标准及允许工具 | 能写出“识别什么 → 执行什么”，且没有影响出题的关键先备知识未知 |
| 收集已有证据 | 看用户原答及获得的帮助；必要时让用户做一道同类题 | 有可判读的独立作答，或明确记录当前只有 Guided 证据 |
| 生成与自检 | 生成一个近迁移候选题，按第 3 节检查 | 题目可解、约束满足、评分依据就绪；否则修订或停止出题 |
| 无提示作答 | 仅展示题目、中性的提交要求和资源规则，然后等待 | 用户提交、求助或退出；不以沉默或耗时判断能力 |
| 判定与反馈 | 先检查题目有效性和协助情况，再按预设标准评估原答 | 给出证据、结果及不确定性；反馈后的修正另记为有帮助表现 |
| 收束 | 给出短记录与一个可选下一步 | 明确本次证明了什么、没有证明什么，不自动启动下一轮 |

若独立同类题尚未完成，先反馈并补足最小缺口；不要用更复杂的迁移题继续测试。帮助后必须用未展示的新题重新收集无提示证据，不能把刚纠正的原题当作独立通过。

## 3. 题目契约与自动自检

### 3.1 候选题规格

生成题目时维护以下简短信息，作答前只展示题干与资源规则。核心技能映射、变化说明、参考解和评分点留到提交后披露，避免提示解题路径。无需输出模型的内部推理过程。

```yaml
transfer_scope: near
core_skill: "一个可观察的目标行为"
source: "训练材料及原题定位"
prerequisites:
  confirmed: []
  unknown: []
variation:
  kind: surface # surface | structure | context
  primary_change: "一个主要变化"
  secondary_change: null # 可选；只能是附带的表面变化
constraints:
  new_concepts: none
  assistance: "off"
  changed_dimensions: 1 # 总数最多 2；不是同时增加两项认知挑战
resources:
  allowed: []
criteria:
  core_application: "什么可观察行为说明核心技能被正确调用"
  complete_result: "任务完成的具体条件"
validation:
  status: pending # pass | reject | uncertain
  basis: [] # 材料依据、参考解核对或实际检查结果
```

`new_concepts: none` 不是“只写一句同一知识点”。候选题需要的非目标知识也必须已经掌握或有明确证据；未知先备知识不能被当作已知。

### 3.2 三类可选变化

一次只选一类主要变化，不要求连续做完三类。

| 类型 | 允许改变 | 必须保持 |
| --- | --- | --- |
| 表面 | 数字、变量名、已知函数形式或数据 | 解题核心规则、步骤负担和先备知识 |
| 结构 | 已学表示方式下的题目布局或表达形式 | 仍只需同一个核心概念；不增加新的规则或嵌套层级 |
| 情境 | 公式或操作换成简单文字情境 | 所需信息直接给出，不要求新领域知识、单位换算或额外建模 |

单纯改变量名可以检查脱离原答案后的执行，但迁移证据很弱。不要用这类题宣称已经能识别结构变化或处理情境变化。

### 3.3 出题前检查

每个候选题必须逐项通过：

1. **目标一致：**题目确实要求调用目标技能；不是复制原答案，也不存在明显绕过目标的捷径。若另一种正确方法能绕过目标，需要另选题，不能把该方法判错。
2. **依赖闭合：**列出的求解依赖均来自已确认知识；未知规则、API、词义或运算不能混入。
3. **变化受控：**一个主要变化，最多附带一个表面变化；不叠加更长计算、更深嵌套、更难阅读等负担。
4. **题目有效：**条件充分、表述无歧义、确有解；开放答案必须有能接受等价解法的标准。
5. **答案可核验：**先形成简短参考解和评分依据，再出题。能用独立推导、教材依据或安全的测试核对时使用，并记录实际执行了什么。不得把未运行测试写成通过。
6. **没有泄漏：**题干、标题、提示语、样例输出和预先展示的测试不包含本题解法或关键结构提示。

不通过则修订；修订一次仍不能确认有效性，就说明具体缺口并停止评分，改用可靠题目或补足材料。这个次数限制用于避免无休止生成，不是教学规律。

同一模型出题和自检存在共同错误风险。自动自检只表示依据当前可用信息接受该题，不等于独立专家审核。题目后来被发现有问题时，撤销该题判定，保留原答，不把责任归给用户。

### 3.4 示例与反例

**链式法则：**训练题 `(x² + 1)³` 可以变为 `(2x² + 3x + 1)³`，前提是多项式求导已经确认。这主要改变内层表达式，不引入新求导规则。

变为 `sin(x² + 3x)` 则必须先确认用户已经会三角函数求导。否则失败可能来自 `sin` 的导数，而不是链式法则。即便先备知识齐全，也应记录外层与内层两个变化；首题优先只改变其中一个。

**编程：**若原任务已经是“循环数字列表，用条件筛选，再加入结果列表”，则可以生成“从字符串列表中保留长度大于 5 的元素”，前提是字符串与 `len` 已学。

如果原材料只是 `for x in numbers` 的遍历，筛选任务额外引入条件判断和结果收集，就不能算受控近迁移。也不能突然要求列表推导式、文件读取或一个完整项目。

## 4. 无提示作答的边界

“无 AI 提示”约束的是作答窗口，不禁止 AI 在提交后反馈。Skill 无法关闭用户的其他应用或证明其未使用外部 AI。

- 开始前约定资源规则：可以保留不替代目标技能的普通工具，例如编辑器、编译器或计算器；默认不使用原解、AI 补全、生成式搜索或直接提供目标解法的工具。
- 资源不能替用户完成被测能力。例如测求导时，符号求导器不能算普通计算器。
- 用统一中性要求收集答案及必要的关键步骤，不预告“使用链式法则”“先找内层函数”等评分点。无需强求冗长解释。
- 作答期间不提供思路、部分答案、代码补全、定向追问或对中间步骤的对错反馈。无关解法的格式澄清可以提供；需要实质修订题意时使该题失效并重新出题。
- 用户可以随时请求帮助或退出。求助时结束该题的独立评估，切换到辅导并标记 `assisted`，不拒绝所需解释，也不把求助等同于能力失败。
- 用户主动更正且尚未收到反馈，仍可作为无提示作答；收到提示后改对只能算有帮助结果。
- 其他工具使用仅记录已知事实或用户报告；未观测的信息标为未知，不推断作弊。

## 5. 评估记录与失败归因

### 5.1 判定顺序

先检查题目是否有效、有没有提示污染、资源是否符合约定，再评估作答。标准须在出题前形成，不能看见答案后临时提高门槛。

| 结果 | 条件 | 可以报告的结论 |
| --- | --- | --- |
| `success` | 有效新题、无提示、核心应用和完整结果都符合标准 | 本次指定变化下的近迁移成功 |
| `partial` | 核心应用有证据，但计算、语法或结果完成仍有局部错误 | 核心调用有证据，任务尚未完整通过 |
| `not_yet` | 有效题的独立作答明确误用或未用出核心技能 | 本次未体现目标近迁移，指出可见错误 |
| `assisted` | 作答中获得了解法相关帮助 | 本题只能作为辅导记录 |
| `inconclusive` | 只有无法判断方法的结果、未提交或证据不足 | 暂无足够证据作结论 |
| `invalid_item` | 新知识混入、题意或参考答案有误、明显可绕过目标等 | 撤销此题的能力判定 |

正确结果不自动证明用出了目标技能。必要时在提交后请用户说明已有步骤，但不能在追问中暗示方法；仍不清楚时保留 `inconclusive`。正确的替代方法应被认可，同时说明它尚未提供目标技能的证据。

### 5.2 错因标签

仅按原答中的证据提出局部假设，不诊断人的能力：

- `recognition`：未识别适用结构，或把训练题表面形式当作规则。
- `application`：识别了结构，但核心规则应用错误。
- `execution`：核心应用正确，计算、语法或局部执行出错。
- `prerequisite`：暴露非目标知识缺口；重新检查题目是否应判无效。
- `unclear`：无法区分原因，保留未知。

同一错误可能有多个原因。最小诊断或补学发生在该次评估结束之后，其答案不得倒填为原先的独立表现。

### 5.3 最小记录与用户输出

保留本次材料定位、目标、题目与变化、出题核验摘要、资源规则、原答或证据引用、协助情况、结果、错因及未验证范围。无需默认记录自信分数、总分或个人能力排名。

用户看到的反馈优先为：

```text
本次结论：……
依据：你的哪一步体现了目标技能，哪里尚未完成。
范围：只验证了哪种变化；长期保持及其他迁移未测。
可选下一步：修补一个缺口，或以后用一道新变式复测。
```

默认不写文件；用户请求导出或继续追踪时，保存最小 checkpoint 到其指定位置。不要承诺删除宿主的聊天日志、自动跨会话记忆或在未来主动唤醒用户。

## 6. 首版验收场景

以下是未来实现的行为验收要求，**不是已经运行或通过的测试**。

| 场景 | 预期行为 |
| --- | --- |
| 有真实原题和独立作答 | 自动检查候选迁移题，合格后直接出题，不增加用户确认环节 |
| 只给“我已经懂了” | 补收一道同类题的独立证据，不据自评标记 Independent |
| 链式法则候选题引入未学的三角函数求导 | 拒绝候选题或澄清先备知识，不将失败归因于链式法则 |
| 单纯遍历训练后生成筛选任务 | 识别额外条件判断/收集依赖，改题 |
| 候选题叠加新规则和长计算 | 拒绝，而不是用“仍是同一主题”放行 |
| 用户尚未提交、正在写中间步骤 | 等待；不评价中间步骤，不透露参考解或结构提示 |
| 用户请求提示或完整答案 | 结束独立窗口，提供辅导；当前题不再计独立成功 |
| 用户在反馈后改对同一道题 | 记录 Assisted，独立复测换新题 |
| 核心应用正确但有算术错误 | `partial`，区分核心证据和结果错误 |
| 用户给出正确但绕过目标的解法 | 接受答案正确性，不误判目标能力通过；检查题目设计 |
| 发现参考答案错误或题意缺陷 | 撤销原判定，解释问题并替换题目 |
| 一道近迁移题通过 | 只报告本次成功，长期保持、其他变化和远迁移仍未知 |
| 要求撤除 AI 后立即完成多知识点项目 | 明确越出 v0.1 范围，建议缩小目标或使用其他流程 |
| 缺少材料、题目自检无法完成 | 报告具体缺口，不伪造题目验证或能力结论 |

实现后用固定对话样例检查出题、等待、求助切换和判定行为，并保留实际输入、输出与失败案例。格式校验通过、模型按协议响应与用户获得可保持的能力，是三种不同证据；前两者不能替代真实学习评估。

## 7. 实现边界与依据

- 建议工作名为 `near-transfer`，尚未创建该 Skill；无需安装、恢复清单或 bootstrap 变更。
- 将来实现时，核心流程放 `SKILL.md`，较长出题规则和验收案例按需放本 Skill 的 `references/`；届时同步 README 入口。
- `project-tech-mentor` 负责技术项目学习，`project-digestion` 负责已有项目机制，`make-sense` 负责即时理解障碍。本 Skill 仅检验指定知识点的近迁移，不接管上述流程。
- 允许做低风险学习练习，不把一次结果当作招聘筛选、资格认证或医疗等高风险工作放行依据。

[前期研究](../research/intentional-learning-in-the-ai-era.md) 是宽范围背景，并非本版执行协议。本次用户澄清将范围收窄：取消必做题组、强制复习调度和泛化学习路线，优先实现可解释的近迁移检查。

“辅助表现不能代替独立表现”的实证背景可见 Bastani 等人发表于 PNAS 的研究：[Generative AI without guardrails can harm learning（2025）](https://doi.org/10.1073/pnas.2422633122)。本设计的题目维度、流程、结果标签及重试上限是设计选择，不是该论文已验证的 Skill 方案。
