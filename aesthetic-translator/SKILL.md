# Aesthetic Translator — 感受 → 规格

定位：品味型翻译层。输入是模糊感受词与参照物，输出是**经用户确认的 Design Read 与设计规格**。不建风格数据（查 `ui-ux-pro-max`），不管页面结构（走 `frontend-guide`）。范围：web 界面为主，含应用型界面（TUI、MD3 类设计系统语境）。

## 统治原则

**翻译 = 给命名选项，不是猜。** 任何维度都不输出裸参数——每个选择都带名字和参照物让用户挑选。两个方向真的分叉且无法从上下文判断时，最多问一个问题，绝不连环追问。

## 核心循环

1. **听**：收集用户的感受词（「高级」「素」「呼吸感」）和提到的参照物（产品名、链接、截图）。参照物权重高于形容词。
2. **定位维度**：判断感受词指向哪些维度（九维度见 `references/dimensions.md`）。默认底色是 `references/east-asian.md` 语料；用户明确点了别的方向（参照物或风格词）时底色退位。
3. **给选项**：每个相关维度给 2-3 个命名选项，各带一行参照物和一句话后果（「这个会让页面安静但显空」）。用户挑，不解释术语。
4. **宣告 Design Read**：一行——「读作：为〈受众〉做的〈物件〉，〈风格名〉语言，底色〈语料名/其他〉，〈密/静/稳〉倾向」。给用户反驳的机会。
5. **输出规格**：四段式 brief——**Context**（谁用、什么设备）/ **Direction**（各维度的具体参数：色值、圆角、阴影、字号、间距、动效毫秒）/ **References** / **Avoid**（反模式清单）。参数要能直接抄进 CSS tokens。
6. **确认后落盘 DESIGN.md**：用户确认方向/brief 后，把设计决定写成所在项目根目录的 `DESIGN.md`（已有则更新，不另建）。token 进 YAML front matter，风格叙述进正文章节；书写/格式规范走 `better-designs-md` skill。这是持久契约——未来会话改 UI 先读它，避免每次重讲品味。

## 三旋钮（内部接口，不向用户暴露数字）

| 旋钮 | 含义 | 典型区间 |
|---|---|---|
| VARIANCE 布局大胆度 | 1 网格严整 ↔ 10 打破网格 | 工具 3-5 / 营销 7-9 |
| MOTION 动效强度 | 1 无动效 ↔ 10 物理弹性 | 生产力 2-4 / 消费 6-8 |
| DENSITY 信息密度 | 1 画廊留白 ↔ 10 驾驶舱 | 阅读产品 2-3 / 终端 7-9 |

推断规则：冷静/极简/编辑 → V 低 M 低 D 低；高级消费 → V 中 M 中 D 低；实验性 → V 高 M 高 D 低；信任优先 → 全低。旋钮值必须翻译成具体参数（D 低 → 间距倍增、行高 1.6+；M 低 → 200ms fade、无弹跳），不留在数字形态。

## 反模式（AI 味警报，写进每份 brief 的 Avoid）

紫色渐变 / stock 插画 / 处处阴影 / 超过两种字体 / emoji 当图标 / 居中三等分卡片 / 纯黑纯白（用 off-white 与 charcoal）/ 无意义玻璃拟态。

## 设计系统语境

项目用 MD3 / Fluent / Carbon 等有官方 token 体系的系统时，只输出方向与参数映射，实现走官方体系，不手搓仿制 CSS。TUI 方向的约束：等宽字体、框线字符、单色 + 一个高亮、无阴影无圆角。
